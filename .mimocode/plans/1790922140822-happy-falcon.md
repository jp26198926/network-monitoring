# Fix: `diagramSelect` resets on Save

## Problem

In `web/public/topology.js`, clicking **Save** (or Ctrl+S) reloads the diagram dropdown and the selected diagram reverts to the first option.

## Root cause

1. `saveDiagram()` succeeds → calls `loadDiagramList()` (`topology.js:757`).
2. `loadDiagramList()` does `dom.diagramSelect.innerHTML = ""` and rebuilds options (`topology.js:687–702`). Rebuilding options drops the browser's selected index, so the select falls back to the first option.
3. Nothing restores the selection afterward.

`renameDiagram()` already works around this by setting `dom.diagramSelect.value = state.current.id` after reloading (`topology.js:801`). `saveDiagram()` has no such restore. Same path is hit by Ctrl+S (`topology.js:1127`).

## Fix

**File:** `web/public/topology.js`

Make `loadDiagramList()` preserve the current diagram selection after rebuilding options (root-cause fix, covers all callers):

```js
async function loadDiagramList() {
  try {
    const res = await fetch("/api/topologies");
    const data = await res.json();
    state.diagrams = data.topologies || [];

    const prev = state.current?.id || dom.diagramSelect.value;
    dom.diagramSelect.innerHTML = "";

    if (!state.diagrams.length) {
      // ... existing empty option ...
      return;
    }

    for (const d of state.diagrams) {
      // ... existing option append ...
    }

    if (prev) dom.diagramSelect.value = prev;
  } catch {
    /* ignore */
  }
}
```

Notes:
- Prefer `state.current?.id` (source of truth for the open diagram) over the raw previous select value.
- After delete, `state.current` is null and the id may no longer exist — assigning a missing value is a no-op; `deleteDiagram()` already opens the next diagram afterward.
- `renameDiagram()`'s manual restore at line 801 becomes redundant but harmless; leave it alone (no drive-by cleanup).

## Alternative considered

One-liner in `saveDiagram()` (`dom.diagramSelect.value = state.current.id` after reload), matching `renameDiagram()`. Rejected: still leaves the wipe-without-restore bug in `loadDiagramList` for future callers.

## Verification

No test suite exists. Manual check via `cd web && npm run dev` (or Electron launcher) and open `/topology.html`:

1. Have 2+ diagrams; open one that is **not** the first in the list.
2. Click **Save** → dropdown must still show that diagram ("Saved ✓" appears, canvas unchanged).
3. Ctrl+S → same.
4. Rename the diagram → dropdown keeps selection and shows the new name.
5. Switch diagrams via the dropdown → still opens the chosen one.
6. New diagram → dropdown selects the new one.
7. Delete a diagram → next diagram opens and is selected.
