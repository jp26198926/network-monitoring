# Live multi-client topology sync

## Goal

When any client creates, saves, renames, or deletes a topology diagram, other clients on `/topology` update automatically:

- Open diagram canvas refreshes (if the viewer is clean).
- `diagramSelect` stays in sync (create / rename / delete).
- If the open diagram is deleted remotely → switch to first remaining diagram (or empty state).
- If the viewer has **unsaved local edits (dirty)** on the same diagram → Modal prompt: **Reload** (discard local) or **Keep mine** (leave canvas alone). Never silently overwrite.
- Own saves must **not** re-apply on the saving client (would clear selection/props).

## Approach

Reuse the existing WS hub (`ws-hub.broadcast`) and client `Live` channel. No changes to `live.js`, `ws-hub.js`, `topology-store.js`, `server.js`, or `modal.js`.

### Protocol

| Type | Payload | When |
|---|---|---|
| `topology.created` | `{ type, clientId, diagram }` | after POST |
| `topology.updated` | `{ type, clientId, diagram }` | after PUT (save **and** rename share this path) |
| `topology.deleted` | `{ type, clientId, id }` | after DELETE |

- Full `diagram` on create/update so receivers paint without a second GET (no fetch race).
- Self-filter via client-generated id: page sets `const CLIENT_ID = uuid()`, sends header `X-Client-Id` on POST/PUT/DELETE; server echoes `req.headers["x-client-id"] || null` as `clientId`. Client no-ops when `msg.clientId === CLIENT_ID`. `broadcast` stays dumb (sends to all sockets including originator).

## Files to change

| File | Change |
|---|---|
| `web/lib/api.js` | `require("./ws-hub")`; broadcast after successful POST / PUT / DELETE topology handlers |
| `web/public/topology.js` | `CLIENT_ID`, headers on 3 mutating fetches, remote-apply helpers, `handleWsMessage` branches, reconnect gap-fill |

## Server (`web/lib/api.js`)

Add `const wsHub = require("./ws-hub");` next to existing requires (no cycle: `ws-hub` only requires `monitor`).

- **POST /api/topologies** (~line 216): after `topologyStore.create(body)` → `wsHub.broadcast({ type: "topology.created", clientId: req.headers["x-client-id"] || null, diagram })`.
- **PUT /api/topologies/:id** (~line 243): after successful `update` → broadcast `topology.updated` with full `diagram`.
- **DELETE /api/topologies/:id** (~line 258): after successful `remove` → broadcast `topology.deleted` with `id`.

Broadcast only after store success. GET unchanged. Do not invent `topology.renamed` (rename is a PUT).

## Client (`web/public/topology.js`)

### Identity + request headers

- `const CLIENT_ID = uuid();` (reuse existing `uuid()` helper — has non-secure-context fallback for `http://<lan-ip>`).
- Add `"X-Client-Id": CLIENT_ID` to headers in `createDiagram` (POST), `saveDiagram` (PUT; also covers `renameDiagram`), `deleteDiagram` (DELETE).

### Helpers

**`applyRemoteDiagram(diagram)`** — paint from the embedded snapshot (no GET):

```js
async function applyRemoteDiagram(diagram) {
  const prevSelection = state.selection;
  state.current = diagram;
  clearDirty();

  if (prevSelection.kind === "node" && state.current.nodes.some((n) => n.id === prevSelection.id)) {
    state.selection = prevSelection;
  } else if (prevSelection.kind === "link" && state.current.links.some((l) => l.id === prevSelection.id)) {
    state.selection = prevSelection;
  } else {
    state.selection = { kind: null, id: null };
    closeProps();
  }

  renderAll();
  dom.diagramSelect.value = diagram.id;
  dom.canvasHint.classList.toggle("hidden", state.current.nodes.length > 0);
}
```

Viewport untouched. Keeps selection if the entity still exists.

**`handleRemoteDeleted(id)`** — mirror local `deleteDiagram` tail (~lines 778–787):

```js
async function handleRemoteDeleted(id) {
  await loadDiagramList();
  if (!state.current || state.current.id !== id) return;

  state.current = null;
  state.selection = { kind: null, id: null };
  clearDirty();
  closeProps();

  if (state.diagrams.length) {
    await openDiagram(state.diagrams[0].id);
  } else {
    renderAll();
    dom.canvasHint.classList.remove("hidden");
    dom.diagramSelect.value = "";
  }
}
```

**`promptRemoteReload(diagram)`** — dirty conflict via `Modal.confirm` (resolves `true`/`false`):

```js
let remotePromptActive = false;
let pendingRemoteDiagram = null;

async function promptRemoteReload(diagram) {
  if (remotePromptActive) {
    pendingRemoteDiagram = diagram; // coalesce rapid saves → latest wins
    return;
  }

  remotePromptActive = true;
  const reload = await Modal.confirm(
    `"${diagram.name}" was changed by another client.\nReload and discard your unsaved edits?`,
    { title: "Diagram changed", okLabel: "Reload", cancelLabel: "Keep mine" },
  );
  remotePromptActive = false;

  const next = pendingRemoteDiagram || diagram;
  pendingRemoteDiagram = null;

  if (reload) await applyRemoteDiagram(next);
  // Keep mine: leave canvas + dirty flag alone; discard pending.
}
```

### `handleWsMessage` branches

Make `async` (Live's `onmessage` already ignores the promise). Insert before the `summary` case:

```js
  if (msg.type === "topology.created") {
    if (msg.clientId && msg.clientId === CLIENT_ID) return;
    await loadDiagramList(); // dropdown only — do not auto-open
    return;
  }

  if (msg.type === "topology.updated") {
    if (msg.clientId && msg.clientId === CLIENT_ID) return;
    if (!msg.diagram) return;

    await loadDiagramList();

    if (!state.current || state.current.id !== msg.diagram.id) return;

    if (state.dirty) await promptRemoteReload(msg.diagram);
    else await applyRemoteDiagram(msg.diagram);
    return;
  }

  if (msg.type === "topology.deleted") {
    if (msg.clientId && msg.clientId === CLIENT_ID) return;
    await handleRemoteDeleted(msg.id);
    return;
  }
```

| Event | Always | If that diagram is open |
|---|---|---|
| `topology.created` | `loadDiagramList()` | nothing (don't steal focus) |
| `topology.updated` | `loadDiagramList()` | dirty → Modal; clean → `applyRemoteDiagram` |
| `topology.deleted` | `loadDiagramList()` | `handleRemoteDeleted` (first remaining or empty) |

Never call `openDiagram` for remote events (extra GET + clears selection). Use `applyRemoteDiagram(msg.diagram)`.

### Reconnect gap-fill

Topology events are WS-only (do **not** extend `live.js` polling). On status transition to `"live"` after a drop, refresh so a reconnect doesn't leave a stale canvas:

```js
let prevLiveStatus = null;

function setLiveStatus(status) {
  // ... existing UI updates ...
  if (status === "live" && prevLiveStatus && prevLiveStatus !== "live") {
    onLiveRestored();
  }
  prevLiveStatus = status;
}

async function onLiveRestored() {
  await loadDiagramList();
  if (state.current && !state.dirty) await openDiagram(state.current.id);
}
```

Skip on the very first connect (`prevLiveStatus` null) so `init()` doesn't double-fetch. Dirty viewers are left alone (next remote update will prompt).

## Edge cases covered

- Rapid remote saves while modal open → single Modal; Reload applies latest pending; Keep discards pending.
- Remote delete of open dirty diagram → switch away, clear dirty (source of truth gone), no Modal.
- Create while peer shows "— No diagrams —" → dropdown updates, canvas stays empty until user picks.
- Own broadcast echo → ignored via `CLIENT_ID`.
- Two dirty clients → last-write-wins on save; each may get a prompt. No OT/CRDT (out of scope).

## Invariants

- Do not make `saveDiagram` call `openDiagram`.
- Do not broadcast on GET.
- Do not filter originator on the server — filter on the client.
- `loadDiagramList` already preserves selection (`state.current?.id`) — safe to call on every remote event.

## Verification (manual, multi-browser)

Setup: `cd web && npm run dev`. Open `/topology` in two browser profiles (A and B). DevTools → WS frames on both.

1. **Create** — A: New "Alpha". B dropdown gains "Alpha"; B canvas unchanged; A selection intact.
2. **Save (clean peer)** — Both open "Alpha". A: add node, Save. B canvas updates; B selection preserved if valid; A keeps its selection/props (own-save no-clobber).
3. **Dirty Keep** — B: dirty edit. A: Save. B gets Modal → **Keep mine** → B canvas/dirty unchanged.
4. **Dirty Reload** — Same → **Reload** → B matches A, dirty cleared.
5. **Rename** — A renames. Both dropdowns show new name; open clean peer updates `state.current.name`.
6. **Delete open** — Both on "Alpha". A deletes. B switches to first remaining (or empty); no Modal; dropdown loses entry.
7. **Delete non-open** — B on "Beta", A deletes "Gamma". B dropdown loses "Gamma"; B canvas untouched.
8. **Create from empty** — A creates after all deleted. B dropdown shows new diagram; canvas empty until selected.
9. **Rapid saves** — B dirty; A saves 3× fast. One Modal; Reload applies final content.
10. **Reconnect** — Brief WS drop → on return to "Live", list refreshes; clean open diagram refetches.
11. **Polling-only** — If WS blocked ("Live (polling)"), device live still works; topology events absent (expected); no errors.

No automated tests in this repo — `cd web && npm run dev` is the only harness.
