# Audit: status fill auto-update + fix gaps

## Verdict

**Mostly yes — colors already update live without refresh.** WS `device.up` / `device.down` / `device.update` / `snapshot` all call `refreshNodeStatuses()` (`topology.js:1027`, `1047`), which toggles `is-up` / `is-down` on the node card (`topology.js:1103-1104`). Binding a device in the props panel re-renders nodes with current status (`renderNodes` at `topology.js:438`).

Two gaps remain:

### Gap 1 — latency-only frames never repaint the fill

`topology.latency` (`topology.js:1051-1070`) can create a live entry with `status: "up"` (first probe result) but only calls `refreshNodeLatencies()`, which updates the ms text and **never** touches `is-up`/`is-down`. A device that first shows up via a latency sample stays unpainted until the next `device.*` or snapshot.

### Gap 2 — stale fill when status is unknown / gone

`refreshNodeStatuses` does `if (!live) continue` (`topology.js:1093`) and leaves whatever `is-up`/`is-down` was already on the card. If a device becomes unknown or is unbound, the green/red fill sticks.

## Fix (client only — `web/public/topology.js`)

1. **In the `latency` branch**, after updating maps, call `refreshNodeStatuses()` (keep `refreshNodeLatencies()` or fold — simplest: call `refreshNodeStatuses()` which already refreshes latency display for nodes with live data; can drop the extra `refreshNodeLatencies()` call or keep both — recommend calling `refreshNodeStatuses()` only, since it updates fill + latency together).

2. **In `refreshNodeStatuses`**, clear fill when there is no live status:

```js
    const el = dom.world.querySelector(`[data-node-id="${node.id}"]`);
    if (!el) continue;

    if (!live) {
      el.classList.remove("is-up", "is-down");
      const ring = el.querySelector(".node-status-ring");
      if (ring) ring.className = "node-status-ring";
      continue;
    }
```

(`live.status === "unknown"` already clears both toggles when `live` exists — that path is fine.)

## Verification

1. Device goes offline → card turns red within ~1s without refresh (existing path).
2. Device comes online → card turns green (existing path).
3. Fresh device that only produced latency samples first → card is green (Gap 1 fix).
4. Unbind device / status unknown → card returns to default dark (Gap 2 fix).
