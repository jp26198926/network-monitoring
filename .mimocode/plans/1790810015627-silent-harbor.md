# Plan: Replace native alert/confirm/prompt with custom modals in `web/`

## Goal

Replace every native browser `alert` / `confirm` / `prompt` in `web/public/` with themed modal dialogs that match the existing dark UI.

## Call sites found (complete)

| File:line | Native API | Purpose |
|---|---|---|
| `web/public/topology.js:751` | `confirm(...)` | Delete diagram confirmation |
| `web/public/topology.js:772` | `prompt(...)` | Rename diagram (text) |
| `web/public/topology.js:1039` | `prompt(...)` | New node type (free text listing types) |
| `web/public/topology.js:1056` | `prompt(...)` | New diagram name (text) |

No `alert()` calls today. Dashboard (`app.js`) has none. Implement all three modal APIs so future use is covered.

## Approach

Small shared vanilla helper — no framework. Theme tokens already in `web/public/style.css` (`--bg`, `--surface`, `--accent`, `--down`, `.btn`, `.hidden`).

### 1. New `web/public/modal.js`

Promise-based API (drop-in async replacement):

```js
// returns Promise<string|null>
Modal.prompt(message, defaultValue, { title, input: "text" | "select", options })

// returns Promise<boolean>
Modal.confirm(message, { title, okLabel, cancelLabel, danger })

// returns Promise<void>
Modal.alert(message, { title, okLabel })
```

Behavior:
- Single reusable DOM overlay created on first use (backdrop + dialog)
- OK → resolve value / `true`; Cancel / Esc / backdrop click → `null` / `false`
- `confirm` with `danger: true` styles OK as `btn-danger` (delete)
- `prompt` with `input: "select"` + `options` renders a `<select>` (used for node type — cleaner than free text listing all types)
- Enter confirms; Esc cancels; focus the input on open
- Text content only (use `textContent`, never `innerHTML` for message/value) to avoid XSS

### 2. Styles — append to `web/public/style.css`

Dark theme modal matching existing panels:

- Backdrop: semi-transparent black
- Dialog: `var(--surface)`, `var(--border)` border, `var(--radius)`
- Title: `var(--text)`; body: `var(--text-muted)`
- Inputs/selects: match `.input` / `.select` styles (check and reuse classes already in `style.css`)
- Footer buttons: Cancel = secondary (border/`btn-secondary` if present, else ghost), OK = `.btn` or `.btn-danger`
- Reuse existing `.btn-danger` from topology toolbar if defined in `topology.css`/`style.css`; if only in topology.css, define `.btn-danger` in `style.css` or put modal + danger styles in `style.css` so both pages can use them

### 3. Wire into `web/public/topology.html`

Add `<script src="modal.js"></script>` before `topology.js` (both at end of body, as topology already does).

Optional but cheap: also add `modal.js` to `index.html` so the dashboard can use it later. Low cost, do it.

### 4. Replace call sites in `web/public/topology.js`

Make the enclosing handlers `async` where needed (`deleteDiagram` and `renameDiagram` already are; `bindEvents` click handlers can be `async`):

```js
// deleteDiagram
if (!(await Modal.confirm(`Delete "${state.current.name}"?`, { title: "Delete diagram", okLabel: "Delete", danger: true }))) return;

// renameDiagram
const name = await Modal.prompt("Diagram name:", state.current.name, { title: "Rename diagram" });
if (!name) return;

// addNodeBtn click
const type = await Modal.prompt("Node type:", "generic", {
  title: "Add node",
  input: "select",
  options: ["router","switch","pc","server","printer","phone","firewall","cloud","generic"],
});
if (type) addNode(type);

// newDiagramBtn click
const name = await Modal.prompt("Diagram name:", "New Diagram", { title: "New diagram" });
if (name) createDiagram(name);
```

Preserve existing empty-string / cancel semantics: cancel → `null` (no-op), OK with empty name → current code already treats falsy name as cancel (`if (!name) return`) — keep that.
