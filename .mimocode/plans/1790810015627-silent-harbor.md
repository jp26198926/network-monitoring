# Plan: Fix LAN topology actions + always stop web server on Electron close

## Root causes (confirmed)

### A. LAN browser: add node / add device broken

`web/public/topology.js:105-107`:

```js
function uuid() {
  return crypto.randomUUID();
}
```

`crypto.randomUUID()` is **secure-context only**. It works in Electron (`http://localhost:<port>`) but is **undefined** in a LAN browser (`http://192.168.x.x:<port>`) → `TypeError` → silent failure on:

- `addNode()` (`+ Node`, `+ Device`) — `topology.js:646`
- Connect mode link create — `topology.js:619`

API writes are fine (no host/CSRF checks). Dashboard does not use `randomUUID`.

### B. Closing Electron leaves web server running

`electron/server-manager.js:316-341` `stopServer()`:

1. `taskkill` `spawnSync` **result is ignored**, then `serverProcess` is force-nulled — failed kills are silent and cannot be retried
2. Custom Windows spawn wraps in `cmd.exe /c` — stored PID is `cmd.exe`, `taskkill /T` can miss the real `node` child
3. Orphans (manual `npm run dev`, crash, Task Manager) are not Electron’s child — nothing to stop
4. Packaged auto-start race: quit between `checkServerPort` and `spawn` can leave a server with no tracked PID

## Fixes

### 1. Secure-context-safe UUID — `web/public/topology.js`

Replace `uuid()` with a generator that works over plain HTTP:

```js
function uuid() {
  if (crypto.randomUUID) return crypto.randomUUID();
  const b = crypto.getRandomValues(new Uint8Array(16));
  b[6] = (b[6] & 0x0f) | 0x40;
  b[8] = (b[8] & 0x3f) | 0x80;
  const h = [...b].map((x) => x.toString(16).padStart(2, "0")).join("");
  return `${h.slice(0,8)}-${h.slice(8,12)}-${h.slice(12,16)}-${h.slice(16,20)}-${h.slice(20)}`;
}
```

`crypto.getRandomValues` works in non-secure contexts.

Also: when `!state.current`, `addNode` / add-device should open the **New diagram** modal (or show `Modal.alert("Create a diagram first")`) instead of silent return.

### 2. Reliable server stop — `electron/server-manager.js`

- Check `taskkill` result (`status`, `stderr`); log failures
- Always also `serverProcess.kill()` as fallback
- If `taskkill` fails, retry once; still null the handle but log clearly
- Keep `spawnSync` (must complete before quit)
- Optional hardening for custom mode: after taskkill, if we can, also `taskkill /IM node.exe` is **too broad** — do **not**. Stick to PID tree + kill()

### 3. Quit-path hardening — `electron/main.js`

- Call `stopServer()` from `before-quit` as well as `will-quit` / `mainWindow.on("closed")`
- In `startBundledAndLoad`, set a `shuttingDown` flag; abort auto-start if already quitting (fixes race)
- `server:start` path: same port pre-check as auto-start (avoid loading a foreign listener)

### 4. Parent-death watchdog — `web/server.js` (orphan safety net)

If spawned by Electron with `stdio: ["pipe","ignore","ignore"]`:

```js
process.stdin.resume();
process.stdin.on("end", () => shutdown());
process.stdin.on("close", () => shutdown());
```

Parent death closes the pipe → child exits even if `taskkill` never ran. Change bundled spawn `stdio` from `"ignore"` to `["pipe", "ignore", "ignore"]` so this works.

(Keep `SIGINT`/`SIGTERM` handlers as they are.)

### 5. Static cache headers — `web/lib/api.js` `serveStatic`

Add `Cache-Control: no-store` so LAN browsers don’t keep stale `topology.js`/`live.js` after edits.

## Verification

1. **LAN add node (the real bug):** from another PC, `http://<host-ip>:3000/topology` → `+ New` diagram → `+ Node` / `+ Device` / Connect — all work (DevTools console has no `randomUUID` TypeError)
2. Same flows still work in Electron (localhost)
3. `npm start` → start server via Launcher → close **main window** → `netstat` / browser `http://localhost:3000` **must fail**; no `node`/`LAN Monitor` orphan
4. Task Manager end the Electron process → within ~2s stdin watchdog stops the web server
5. Hard refresh the LAN browser after rebuild — no stale JS
6. If no diagram is open, `+ Node` prompts to create one instead of doing nothing
