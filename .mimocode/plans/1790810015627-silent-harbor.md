# Plan: Add Mac/Linux electron-builder targets

## Goal

Extend the existing Windows packaging so Mac and Linux installers can be built later, without changing runtime behavior. Rebuild-after-`web/`-edits stays the same (`npm run build` family).

## Scope

Config-only in root `package.json`. No changes to `electron/`, `web/`, or `renderer/`. Windows scripts/output names stay as they are.

## Platform note (important)

electron-builder must run **on** the target OS for reliable output:

| Target | Build on | Output |
|---|---|---|
| Windows NSIS | Windows | `dist/LAN Monitor-1.0.0-setup.exe` (already works) |
| macOS | macOS | `dist/LAN Monitor-1.0.0.dmg` + `.zip` |
| Linux | Linux | `dist/LAN Monitor-1.0.0.AppImage` + `.deb` |

Cross-building Mac from Windows is not supported for dmg; Linux AppImage from Windows is possible but flaky. Plan assumes you copy the repo (or clone) to a Mac/Linux machine and run the script there.

## Changes — root `package.json`

### 1. Scripts

```json
"scripts": {
  "start": "electron .",
  "prebuild": "npm --prefix web install --omit=dev",
  "build": "electron-builder --win nsis",
  "build:dir": "electron-builder --win dir",
  "build:mac": "electron-builder --mac",
  "build:linux": "electron-builder --linux",
  "build:all": "electron-builder --win --mac --linux"
}
```

- `build` / `build:dir` unchanged (Windows workflow)
- `build:mac` / `build:linux` — run on those OSes
- `build:all` — only useful if somehow run with all toolchains; rarely used, included for completeness

`prebuild` already runs before `build*` via npm lifecycle (`prebuild` only hooks `build`). **Problem:** npm only runs `pre*` for the exact script name — `prebuild` does **not** run before `build:mac` / `build:linux`. Fix by renaming or adding explicit hooks:

```json
"prebuild": "npm --prefix web install --omit=dev",
"prebuild:mac": "npm --prefix web install --omit=dev",
"prebuild:linux": "npm --prefix web install --omit=dev",
"prebuild:all": "npm --prefix web install --omit=dev"
```

(Or simpler: call `npm --prefix web install --omit=dev && electron-builder ...` inline in each build script and drop `pre*` hooks. Prefer **inline** to avoid hook-name surprises.)

Recommended final scripts:

```json
"scripts": {
  "start": "electron .",
  "deps:web": "npm --prefix web install --omit=dev",
  "build": "npm run deps:web && electron-builder --win nsis",
  "build:dir": "npm run deps:web && electron-builder --win dir",
  "build:mac": "npm run deps:web && electron-builder --mac",
  "build:linux": "npm run deps:web && electron-builder --linux"
}
```

### 2. `build.mac`

```json
"mac": {
  "target": ["dmg", "zip"],
  "category": "public.app-category.utilities",
  "identity": null
}
```

- `identity: null` skips code signing (unsigned local builds). If you later distribute outside your machines, replace with a Developer ID.
- `zip` is useful if you later add auto-update.
- Default icon is fine unless you add `buildResources/icon.icns` later.

### 3. `build.linux`

```json
"linux": {
  "target": ["AppImage", "deb"],
  "category": "Network",
  "maintainer": "LAN Monitor"
}
```

- AppImage: run anywhere, no install
- deb: Debian/Ubuntu install
- Same bundled `web/` via existing `extraResources` — no change needed

### 4. Leave unchanged

- `files`, `extraResources`, `appId`, `productName`, `nsis` block
- `win` block (can leave `target: ["nsis"]`)
- All of `electron/`, `web/`, `renderer/` — Unix stop path already uses `SIGTERM`; bundled spawn uses `process.execPath` + `ELECTRON_RUN_AS_NODE` (works on mac/linux)

## Verification

On this Windows machine (config sanity only):

1. `npm run build:dir` still works and still packs `resources/web` + `ws` (no regression)
2. `npm run build` still produces `dist/LAN Monitor-1.0.0-setup.exe`

On a Mac (when you get there):

3. `npm install && npm run build:mac`
4. Confirm `dist/mac/LAN Monitor.app` (or `dist/mac-arm64/`) exists, open it, dashboard auto-starts at `http://localhost:3000`
5. Confirm `resources/web` inside the `.app` (`LAN Monitor.app/Contents/Resources/web/`) has `server.js` + `node_modules/ws` and no `data/`
6. First run: macOS may ask for Local Network permission — allow for LAN monitoring

On Linux (when you get there):

7. `npm install && npm run build:linux`
8. Run the AppImage — same auto-start and `resources/app.asar.unpacked` or `resources/web` layout check (`web/` is extraResources so it lives under the AppImage mount `resources/web/`)
9. `ping`/`arp`/`nbtstat` — Linux monitoring uses `ping`/`arp` (see `web/lib/`); `nbtstat` is Windows-only and already optional

## Out of scope

- Code signing / notarization (macOS Gatekeeper will warn on unsigned apps)
- Icons
- Auto-update
- CI matrix (GitHub Actions macos/linux runners) — can be added later
- Runtime code changes (not needed for this)
