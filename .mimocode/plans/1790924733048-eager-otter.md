# Users CRUD + Role-Based Access Control (`web/`)

## Goal

Add a Users page with CRUD and three roles (admin / technician / viewer), plus a login flow that gates mutations. Dashboard and topology stay publicly **viewable**; login (popup modal) is required to mutate topology, edit settings, trigger scan, or open the Users page.

## Confirmed requirements

| Role | Dashboard (settings + scan) | Topology (add/edit/delete/save) | Users page |
|---|---|---|---|
| **admin** | full CRUD | full CRUD | full CRUD |
| **technician** | full CRUD | full CRUD | no access |
| **viewer** | view only | view only | no access |
| **anonymous** | view only | view only | no access |

- Dashboard "CRUD" = edit monitoring settings + trigger scan. **No device CRUD** (devices stay auto-discovered, read-only).
- Default seeded account: `admin` / `admin` (changeable later).
- Any logged-in user can change their own password; admin can create/edit/delete all users (including passwords and roles).
- Auth: popup login modal (Login button in header). **HttpOnly cookie session** — works in Electron (`http://localhost:<port>` is Chromium). No new npm deps (password hashing via `node:crypto` scrypt).

## Architecture facts (verified)

- Hand-rolled router in `lib/api.js` (`handleApi` + `serveStatic`). No framework. Only dep: `ws`.
- SQLite via `node:sqlite` in `lib/db.js`; schema in `db.open()`; topologies in JSON file (`lib/topology-store.js`).
- Multi-page vanilla JS frontend; shared `modal.js` / `live.js` / `style.css` (dark theme CSS vars). Nav duplicated in each HTML header.
- No auth exists anywhere today.
- Conventions: camelCase DTOs wrapped in named keys (`{devices}`, `{diagram}`), errors `{error}` with 400/404/500. Settings PUT uses field allowlist — reuse that pattern. Laravel-style banner comments in `lib/`.
- `Modal` only supports a single text/select input → login and user forms need a small custom multi-field modal (or extend `modal.js`). Plan: custom overlay for login + user form (username/password/role), reuse `Modal.confirm` for delete.

## Implementation

### 1. DB — `web/lib/db.js`

Add to the `db.exec` block in `open()`:

```sql
CREATE TABLE IF NOT EXISTS users (
  id INTEGER PRIMARY KEY,
  username TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  role TEXT NOT NULL DEFAULT 'viewer',   -- admin | technician | viewer
  created_at INTEGER NOT NULL,
  updated_at INTEGER NOT NULL
);
```

After schema creation, **seed default admin if `users` is empty**:
- username `admin`, password `admin`, role `admin`
- hash format: `scrypt$<saltHex>$<hashHex>` via `node:crypto` (`scryptSync(password, salt, 32)`; salt = 16 random bytes). Verify with timing-safe compare.

New helpers (exported alongside devices):
- `countUsers()`, `listUsers()` (omit `password_hash`), `getUserById(id)`, `getUserByUsername(username)`
- `createUser({ username, password, role })`, `updateUser(id, { username?, password?, role? })`, `deleteUser(id)`
- `verifyPassword(user, password) -> boolean`, `hashPassword(password) -> string`
- Role validation: only `admin` | `technician` | `viewer`; username non-empty trimmed unique.

### 2. Sessions — `web/lib/auth.js` (new)

In-memory `Map<token, { userId, username, role, createdAt }>` + cookie name `lan_session` (HttpOnly, SameSite=Lax, Path=/). Token = `crypto.randomBytes(32).toString("hex")`. Simple expiry (e.g. 7 days, sliding optional — fixed expiry is fine).

Exports: `createSession(user) -> token`, `destroySession(token)`, `getSession(token)`, `parseCookies(req)`, `hashPassword` / `verifyPassword` (or keep hashing in db.js — pick one place; recommend `auth.js` for hashing+sessions, db.js calls it).

**Why cookie not localStorage token**: Electron Chromium stores cookies for `http://localhost` normally; HttpOnly keeps the token out of JS. No fallback needed.

### 3. API routes — `web/lib/api.js`

**Public (no auth):**
- All existing GET routes: `/api/summary`, `/api/devices`, `/api/devices/:id`, `/api/devices/:id/history`, `/api/events`, `/api/adapters`, `/api/settings` (read), `/api/topologies`, `/api/topologies/:id`
- Static pages: `/`, `/topology`, assets
- `POST /api/auth/login`

**Any logged-in user (admin/technician/viewer):**
- `GET /api/auth/me` → `{ user: { id, username, role } }` (401 if anonymous — frontend uses this to render header state)
- `POST /api/auth/logout` → `{ ok: true }` (clears cookie; also fine if anonymous)
- `PUT /api/auth/password` → body `{ currentPassword, newPassword }` → `{ ok: true }`; 400 on wrong current / weak empty; used for "change my password"

**admin or technician (mutations):**
- `PUT /api/settings` (existing allowlist)
- `POST /api/scan`
- `POST /api/topologies`, `PUT /api/topologies/:id`, `DELETE /api/topologies/:id`

**admin only:**
- `GET /api/users` → `{ users: [{ id, username, role, createdAt, updatedAt }] }`
- `POST /api/users` → body `{ username, password, role }` → `201 { user }` (400 on dup username / bad role / empty password)
- `GET /api/users/:id` → `{ user }`
- `PUT /api/users/:id` → body `{ username?, password?, role? }` (empty/missing password = keep current) → `{ user }`
- `DELETE /api/users/:id` → `{ ok: true }` (400 if deleting own account or last admin)

**Gate helper** inside `handleApi` (e.g. `requireAuth(req, roles?)` returning session or sending 401/403):
- 401 `{ error: "Unauthorized" }` when no/invalid session
- 403 `{ error: "Forbidden" }` when role not allowed
- Parse cookie from `req.headers.cookie` via `auth.parseCookies`

**Static:** add rewrite `pathname === "/users" || pathname === "/users/"` → `users.html` (same pattern as `/topology`).

**WebSocket (`lib/ws-hub.js`)**: keep live broadcasts public (read-only data). Leave client `{type:"refresh"}` ungated OR gate it as a mutation — **recommend leaving it** (minor; scan is already gated over HTTP and a LAN viewer forcing a sweep is harmless). No change required unless trivial.

### 4. Frontend

#### 4a. Shared auth UI — `web/public/auth.js` (new, loaded by all pages)

- `Auth.ensure()` → fetches `GET /api/auth/me`; caches `{ user }` or `null`.
- Renders header account area into a placeholder div (e.g. `#accountArea`):
  - anonymous: **Login** button
  - logged-in: `username (role)` + **Logout** + **Account** (change password) + **Users** link (admin only)
- **Login modal** (custom overlay, styled like `.modal-*`): username + password fields, error text, submit on Enter, Cancel. `POST /api/auth/login` with JSON body; on success set cookie is automatic → re-render header.
- **Change-password modal**: current, new, confirm; `PUT /api/auth/password`.
- Export `Auth.requireRole(role)` helpers used by page scripts to show/hide mutation controls.
- Nav "Users" link: only injected/shown for admin.

#### 4b. Nav updates

- `index.html` + `topology.html`: add `<a href="/users">Users</a>` (hidden by default, shown by `auth.js` when admin) and `<div id="accountArea"></div>` in `header-actions`. Script tag for `auth.js` before page scripts.

#### 4c. Dashboard gating — `public/app.js` + `index.html`

- `#refreshBtn` ("Scan now") and settings edit entry (if/when present in UI — currently settings are API-only; if there is no settings UI, just gate `PUT /api/settings` / `POST /api/scan` server-side and disable `#refreshBtn` for anonymous/viewer).
- After `Auth.ensure()`: if role is admin/technician → enable Scan now; else disable/hide it. Clicking while anonymous opens the login modal.

#### 4d. Topology gating — `public/topology.js` + `topology.html`

- Mutation controls: New, Rename, Delete, Save, + Node, + Device, connect mode — for anonymous/viewer: disable buttons (or intercept clicks → open login modal when anonymous; if logged-in viewer, show "view only" notice).
- Local edits without save are fine to block up front (disable edit tools) so viewer can pan/zoom/view only.
- `Auth.ensure()` on boot; re-apply after login success (header + tool state).

#### 4e. Users page — `public/users.html` + `public/users.js` (+ styles in `style.css` or small `users.css`)

- Header same pattern as other pages (brand + nav + accountArea).
- Table: username, role (badge), created, updated, actions (Edit / Delete).
- Toolbar: **+ Add user** button.
- Create/Edit modal (custom, multi-field): username, password (placeholder "leave blank to keep" on edit), role `<select>` (admin/technician/viewer).
- Delete: `Modal.confirm` with danger style.
- Self-protections client-side (mirror server): disable delete on own row; admin can edit anyone.
- On load: `GET /api/users`; if 401/403 → redirect to `/` (or show access denied).
- Reuse `.device-table`, `.btn`, `.badge`, `.btn-danger` from `style.css`.
